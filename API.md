# API инструмента отбора признаков

Базовый адрес при локальной работе: `http://localhost:8000`

Все ответы - JSON. Все даты - в формате ISO 8601.

Тем же приложением раздаётся и собранный веб-интерфейс, так что сервер
один и адрес один. Автоматическая схема запросов доступна на `/api/docs`.

---

## Справочники

Нужны, чтобы интерфейс знал, что показывать.

### `GET /api/features`
Список всех признаков, которые умеет считать программа.

```json
{
  "total": 41,
  "spectral": 9,
  "textural": 32,
  "items": [
    { "index": 0, "name": "Norm_B2", "group": "spectral", "window": null,
      "description": "Нормализованный канал B2 (синий)" },
    { "index": 9, "name": "Mean_3", "group": "textural", "window": 3,
      "description": "Среднее значение яркости, окно 3×3" }
  ]
}
```

### `GET /api/feature-sets`
Наборы признаков: встроенные и добавленные исследователем в папку
`user_features`. Пользовательские наборы подгружаются при каждом
обращении, так что новый файл виден без перезапуска сервера.

```json
{
  "items": [
    { "id": "spectral", "name": "Спектральные",
      "description": "Нормализованные каналы снимка и индексы NDVI, NDWI, NDBI.",
      "needs_channels": true, "builtin": true },
    { "id": "texture", "name": "Текстурные",
      "description": "Среднее и дисперсия яркости в скользящем окне...",
      "needs_channels": false, "builtin": true },
    { "id": "gradient", "name": "Градиентные",
      "description": "Пример пользовательского набора",
      "needs_channels": false, "builtin": false }
  ]
}
```

### `GET /api/criteria`
Доступные критерии отбора - из них собирается «меню» на странице.

```json
{
  "items": [
    { "id": "bhattacharyya", "name": "Расстояние Бхаттачарьи",
      "type": "filter", "speed": "fast", "scope": "pair",
      "unit": "расстояние", "classifier_free": true, "color": "#14664A",
      "description": "Оценивает разделимость пары классов. Не привязан к классификатору." },
    { "id": "knn", "name": "Отбор через kNN",
      "type": "wrapper", "speed": "slow", "scope": "all",
      "unit": "точность", "classifier_free": false, "color": "#B4531F",
      "description": "Оценивает все классы сразу через точность классификатора." }
  ]
}
```

`scope` показывает, работает критерий с парой классов (`pair`) или со
всеми сразу (`all`) - от этого зависит, нужно ли спрашивать у
пользователя пару классов.

### `GET /api/classes`
Список классов датасета. Названия берутся из `dataset.json`; если
описания нет - отдаются встроенные.

```json
{
  "items": [
    { "id": 1, "name": "Плотная застройка" },
    { "id": 2, "name": "Разреженная застройка" }
  ]
}
```

### `GET /api/presets`
Готовые режимы прогона.

```json
{
  "items": [
    { "id": "fast", "name": "Быстрый", "description": "10 патчей, для проверки" },
    { "id": "research", "name": "Исследовательский", "description": "50 патчей" },
    { "id": "thinned", "name": "Прореживание", "description": "~150 патчей, все классы гарантированно" },
    { "id": "full", "name": "Полный", "description": "весь датасет, считается долго" }
  ]
}
```

### `GET /api/dataset`
Что за данные сейчас подключены и что на них получится посчитать.
Описание берётся из `dataset.json` в корне проекта.

```json
{
  "ok": true,
  "dataset": {
    "name": "MultiSenGE",
    "n_bands": 10,
    "band_order": ["B2", "B3", "B4", "B5", "B6", "B7", "B8", "B8A", "B11", "B12"],
    "band_roles": { "blue": "B2", "green": "B3", "red": "B4", "nir": "B8", "swir": "B11" },
    "feature_bands": ["B2", "B4", "B8", "B11", "B12"],
    "n_spectral": 9,
    "n_textural": 32,
    "n_features": 41,
    "n_classes": 14,
    "classes": [ { "id": 1, "name": "Плотная застройка" } ],
    "indices_available": ["NDVI", "NDWI", "NDBI"],
    "indices_missing": [],
    "n_pairs": 1911
  },
  "notes": []
}
```

Если файла нет или в нём ошибка, ответ приходит с кодом 200, но с
`ok: false` - чтобы страница показала текст ошибки, а не упала:

```json
{ "ok": false, "error": "В описании указано 10 каналов, а в файле их 4..." }
```

`notes` - это замечания, а не ошибки: работать можно, но стоит знать.
Например, что какой-то индекс не посчитается из-за незаданной роли канала.

## Запуск расчёта

### `POST /api/runs`
Ставит задачу и **сразу** возвращает её идентификатор. Расчёт идёт в
фоновом потоке и не зависит от того, открыта ли страница.

Тело запроса:
```json
{
  "preset": "thinned",
  "criteria": ["bhattacharyya", "mahalanobis", "mutual_info", "knn"],
  "max_features": 15,
  "bhatta_pair": [2, 11],
  "window_sizes": [3, 5, 7, 9],
  "use_spectral": true
}
```

Обязательное поле только `preset`. Остальные необязательные: при
отсутствии берутся значения из пресета. `max_features` - от 1 до 41,
`bhatta_pair` - ровно два номера класса.

Ответ `202 Accepted`:
```json
{ "task_id": "a3f2b1c8", "status": "queued", "created_at": "2026-07-31T14:03:00" }
```

### `GET /api/runs`
Список задач в памяти сервера. Нужен, чтобы страница подхватила уже
идущий расчёт - например, после обновления страницы или если её открыли
в другой вкладке.

Параметр `active_only` (по умолчанию `true`) оставляет только задачи со
статусом `queued` или `running`.

```json
{
  "total": 1,
  "items": [
    { "task_id": "a3f2b1c8", "status": "running", "stage": "Отбор признаков",
      "progress": 0.55, "elapsed_sec": 74.2, "preset": "thinned",
      "criteria": ["bhattacharyya", "knn"], "created_at": "2026-07-31T14:03:00" }
  ]
}
```

### `GET /api/runs/{task_id}`
Статус одной задачи. Интерфейс опрашивает его раз в 1–2 секунды, пока
идёт расчёт.

```json
{
  "task_id": "a3f2b1c8",
  "status": "running",
  "stage": "Отбор признаков",
  "progress": 0.55,
  "log_tail": [
    "Шаг 5: признак # 0, Acc=0.7404 (+0.0130)",
    "Шаг 6: признак # 7, Acc=0.7453 (+0.0050)"
  ],
  "elapsed_sec": 74.2,
  "error": null
}
```

`status` принимает значения: `queued`, `running`, `done`, `failed`,
`cancelled`. Когда `status = "failed"`, в поле `error` лежит текст ошибки.

### `POST /api/runs/{task_id}/cancel`
Останавливает расчёт, но оставляет задачу - чтобы страница могла
показать, что он был отменён, а не просто исчез.

```json
{ "task_id": "a3f2b1c8", "cancelling": true }
```

Отмена не мгновенная: критерий проверяет флаг между шагами отбора, так
что задача перейдёт в `cancelled` через секунду-другую. Если расчёт уже
завершён - `409 Conflict`.

### `GET /api/runs/{task_id}/result`
Результаты. Доступны, когда `status = "done"`, иначе `409 Conflict`.

Если задачи уже нет в памяти (например, сервер перезапускали), результат
ищется в истории - так ссылка на результат продолжает работать.

```json
{
  "task_id": "a3f2b1c8",
  "params": { "preset": "thinned", "n_patches": 150 },
  "dataset": { "n_pixels": 9830400, "n_classes": 14, "n_features": 41 },
  "criteria": [
    {
      "id": "bhattacharyya",
      "selected": [17, 5, 2, 9, 33],
      "selected_names": ["Mean_5", "Norm_B12", "Norm_B4", "Mean_3", "Mean_9"],
      "history": [0.4132, 0.6831, 1.1370, 1.2782, 1.3834],
      "accuracy": 0.752,
      "error_rate": 0.248,
      "f1_macro": 0.364,
      "time_sec": 1.1
    }
  ],
  "agreement": {
    "all": ["Norm_B11", "Norm_B4"],
    "majority": ["Mean_3", "Mean_7", "NDBI", "NDVI", "NDWI", "Norm_B12"],
    "unique": { "mahalanobis": ["Rho_90_9"], "knn": [] },
    "pairs": [
      { "a": "bhattacharyya", "b": "mahalanobis", "features": ["Mean_3", "NDVI"] }
    ],
    "n_criteria": 4
  },
  "distances": {
    "class_ids": [1, 2, 3],
    "bhattacharyya": [[0.0, 0.34, 1.18], [0.34, 0.0, 0.77], [1.18, 0.77, 0.0]],
    "mahalanobis": [[0.0, 0.82, 1.00], [0.82, 0.0, 0.80], [1.00, 0.80, 0.0]]
  },
  "total_time_sec": 139.0
}
```

`agreement` приходит, когда критериев два и больше: `all` - признаки,
которые выбрали все критерии, `majority` - больше половины, `unique` -
что взял только один критерий, `pairs` - попарные пересечения наборов.

`history` - значения критерия после добавления каждого очередного
признака; по ним рисуется кривая прироста. Единица измерения у каждого
критерия своя, она указана в `unit` из `/api/criteria`.

Числовые данные отдаются как есть - графики интерфейс рисует сам,
картинки с сервера не передаются.

### `DELETE /api/runs/{task_id}`
Останавливает задачу и убирает её из памяти. В истории запись остаётся.

## История расчётов

Законченные расчёты сохраняются в базу (SQLite, файл `results/history.db`)
и доступны после перезапуска сервера.

### `GET /api/history?limit=50`
Список прошлых расчётов, свежие сверху. `limit` - от 1 до 200,
иначе `422`.

```json
{
  "total": 12,
  "items": [
    {
      "task_id": "a3f2b1c8",
      "created_at": "2026-07-31T18:00:00",
      "preset": "thinned",
      "criteria": ["bhattacharyya", "knn"],
      "n_pixels": 9830400,
      "n_classes": 14,
      "total_time_sec": 139.0,
      "accuracies": { "bhattacharyya": 0.752, "knn": 0.755 }
    }
  ]
}
```

### `GET /api/history/{task_id}`
Полный результат сохранённого расчёта - тот же формат, что у
`GET /api/runs/{task_id}/result`.

### `DELETE /api/history/{task_id}`
Удаляет запись из истории.

## Служебное

### `GET /api/health`
Проверка, что сервер жив, и сколько задач он сейчас держит.

```json
{ "status": "ok", "tasks_total": 3, "tasks_active": 1 }
```

---

## Коды ответов

| Код | Когда |
|-----|-------|
| 200 | Всё хорошо |
| 202 | Задача принята в работу |
| 404 | Такой задачи или записи нет |
| 409 | Результат ещё не готов, задача упала или уже завершена |
| 422 | Ошибка в параметрах запроса |
