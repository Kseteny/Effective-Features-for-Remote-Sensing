# Effective Features for Remote Sensing

Инструмент для сравнения методов отбора признаков в задачах классификации
данных дистанционного зондирования Земли.

Когда для классификации снимка считается несколько десятков признаков,
далеко не все они полезны: часть дублирует друг друга, часть почти не
разделяет классы. Этот инструмент позволяет отобрать компактный набор
разными методами и посмотреть, насколько результаты сходятся между собой
и во что обходится каждый метод по времени.

Работает как веб-приложение в браузере и как обычный скрипт из командной
строки.

## Что умеет

**Четыре критерия отбора:**

| Критерий | Тип | Идея |
|---|---|---|
| Расстояние Бхаттачарьи | без классификатора | статистическая разделимость пары классов |
| Расстояние Махаланобиса | без классификатора | усреднение по всем парам классов, устойчивее на редких классах |
| Взаимная информация | без классификатора | информативность минус избыточность (штраф по максимальной корреляции с уже отобранными) |
| Отбор через kNN | обёртка | жадное наращивание набора по точности классификатора |

Первые три не требуют обучения классификатора и работают на порядки
быстрее обёртки — сравнение их качества и есть основной сценарий работы
с инструментом.

**Признаки.** Базовый набор — 41 признак: 9 спектральных
(нормализованные каналы, NDVI, NDWI, NDBI) и 32 текстурных (среднее и
дисперсия в скользящем окне, корреляция соседних пикселей по четырём
направлениям, их среднее и разброс — по 8 признаков на каждый из четырёх
размеров окна 3, 5, 7, 9). Набор расширяемый: свои признаки можно
подключить, не трогая код пакета.

**Оценка.** Отобранные наборы проверяются на контрольной выборке
(разбиение 70/30 со стратификацией): точность, вероятность ошибки,
F1-macro. Замеряется время работы каждого критерия.

**Интерфейс.** Выбор критериев и классов, сетка признаков с подсветкой
совпадений между критериями, кривые прироста качества с ползунком по
размеру набора, история расчётов, отмена длинного прогона.

## Установка

Нужны Python 3.10+ и Node.js LTS (второй — только для веб-интерфейса;
без него расчёты работают из командной строки).

**Windows.** Запустить `install.bat` — он создаст виртуальное окружение,
поставит зависимости и соберёт фронтенд. Дальше `start.bat` поднимает
сервер и открывает браузер.

**Вручную (любая ОС):**

```
python -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt

cd web && npm install && npm run generate && cd ..

cd src && python -m uvicorn effective_features.api:app --port 8000
```

Интерфейс — на http://localhost:8000

## Данные

Снимки в репозиторий не входят. По умолчанию инструмент настроен на
**MultiSenGE** — 1911 патчей Sentinel-2 размером 256×256 с разметкой по
14 классам землепользования для региона Гранд-Эст (Франция).
Датасет открытый, описан в статье Wenger et al., 2022.

Ожидаемая раскладка:

```
data/s2_pref/            снимки
data/ground_reference/   маски классов
lists/                   списки файлов
```

## Подключение своего датасета

Всё описание данных вынесено в `dataset.json` — в коде ничего не зашито.
Достаточно указать пути, порядок спектральных каналов, роли каналов
(какой считать красным, какой ближним ИК и т.д.) и названия классов:

```json
{
  "name": "Мой датасет",
  "images_dir": "data/images",
  "masks_dir": "data/masks",
  "band_order": ["B2", "B3", "B4", "B8"],
  "band_roles": { "blue": "B2", "green": "B3", "red": "B4", "nir": "B8" },
  "classes": { "1": "Город", "2": "Лес" }
}
```

Спектральные индексы считаются только те, для которых есть нужные каналы:
если ИК-канала нет, NDVI просто не появится в списке признаков.

Проверить, что данные читаются, можно через `check_dataset.py`.

## Добавление своих признаков

Создать папку `user_features` рядом с `src` и положить туда .py-файл:

```python
from effective_features.feature_sets import register

def compute(ctx):
    red = ctx.band('red')
    return {'my_feature': some_function(red)}

register(
    id='my_set',
    name='Мой набор',
    description='Что он считает',
    compute=compute,
)
```

Набор появится в интерфейсе автоматически. Пример — в
`user_features/example_gradient.py.txt`.

Новый критерий отбора добавляется похоже — через `register()` в
`criteria.py`.

## Расчёты из командной строки

```
cd src
python -m effective_features.run_experiment
```

Меню предложит быстрый режим (отладка на нескольких патчах) и
исследовательский (несколько сидов, усреднение, сравнение критериев).
Сиды можно задать вручную или сгенерировать случайно — они выводятся в
лог, чтобы прогон можно было повторить.

Отдельно: `volume_experiment.py` — зависимость качества от объёма
выборки, `visualize.py` — графики, `recompare.py` — пересборка отчётов
по готовым результатам.

Результаты складываются в `results/`: CSV с ранжированием признаков и
текстовая сводка по согласию критериев и эффективности.

## Кэш

Признаки для каждого патча считаются один раз и складываются в `cache/`.
Повторный прогон с теми же настройками читает готовое — это примерно
на порядок быстрее. Ключ кэша учитывает состав наборов признаков и
размеры окон, так что при их изменении пересчёт происходит сам.

Если состав признаков менялся, а старый кэш жалко — `migrate_cache.py`
переносит совместимую часть.

## Структура

```
src/effective_features/
  config.py         параметры прогона
  dataset.py        описание датасета из dataset.json
  features.py       вычисление признаков, кэш, прореживание выборки
  feature_sets.py   реестр наборов признаков
  criteria.py       реестр критериев отбора
  selectors.py      сами алгоритмы отбора и оценка на контроле
  compare.py        сведение результатов нескольких прогонов
  api.py            HTTP-сервер (FastAPI)
  storage.py        история расчётов (SQLite)
web/                интерфейс (Nuxt + TypeScript)
```

Описание HTTP-эндпоинтов — в [API.md](API.md).

## Особенности данных, о которых стоит знать

У MultiSenGE сильный дисбаланс классов: пахотные земли, леса и луга
занимают почти всё, а редкие классы — доли процента. Из-за этого при
увеличении выборки точность классификации не растёт, а снижается:
пропорции классов сходятся к истинным, и редкие классы начинают портить
усреднённые метрики. Это свойство данных, а не ошибка инструмента.

Чтобы редкие классы не выпадали совсем, выборка патчей делается
систематическим прореживанием с гарантированным добором патчей, где эти
классы встречаются.
